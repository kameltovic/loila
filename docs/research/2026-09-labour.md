# Travail / conventions collectives — recherche sources (sept. 2026)

Mission : construire « Quelle convention collective s'applique ? » puis des calculateurs
(préavis, indemnités, congés, minima, ancienneté, heures sup, jours fériés, HCR).

Méthode : chaque source ci-dessous a été vérifiée en direct (`curl`, `webfetch`, `websearch`)
le 21/09/2026. Les réponses sont reproduites tronquées. Aucune donnée n'est inventée ; ce qui
n'a pas pu être vérifié est signalé comme tel.

---

## 1. Synthèse et recommandation

### Ce qui est établi

- **SIRET → IDCC est officiel et exploitable.** Le ministère du Travail publie un jeu de données
  « Liste des conventions collectives par entreprise (SIRET) », issu de la **DSN**, sous
  **Licence Ouverte 2.0** (`data.gouv`, id `5e7201d522f2a43e9f736a9a`). Il contient 2 365 706
  lignes pour le mois 2026-07 (2 117 487 SIRET distincts). L'API publique **recherche-entreprises**
  (DINUM) expose la même information (`siege.liste_idcc`, `complements.liste_idcc`) sans
  authentification, à 7 req/s.
- **La liste officielle à jour des conventions** est le « fichier de suivi historique » de la
  **Dares/DG Travail**, mis à jour mensuellement depuis le 1er juin 2026 (elle remplace la liste
  mensuelle antérieure). Il donne, pour chaque IDCC : libellé, régime, champ, **actif/inactif**,
  dates. Les 18 conventions de Loilà y sont toutes `actif = 1`.
- **Les textes** sont dans **KALI** (DILA, Licence Ouverte 2.0), dump XML quotidien + miroir git
  (déjà ingéré par Loilà). Les grilles de salaires minima y sont dans des **tables HTML**
  (`<table>`), donc extractibles, mais hétérogènes.
- **Le SMIC** n'a **pas** de jeu de données ouvert officiel : la source de vérité est
  l'Urssaf (+ l'arrêté de relèvement). Valeurs 2026 vérifiées : 12,02 €/h au 01/01, 12,31 €/h
  au 01/06 (1 823,03 € puis 1 867,02 €/mois).
- **NAF → IDCC n'est PAS déterminant.** C'est un indice (la doctrine et la Dares le disent) :
  un même APE renvoie à plusieurs IDCC et l'activité réelle prime. Il ne doit jamais produire
  une convention « certaine ».

### Recommandation « Trouver ma convention collective »

1. **SIRET en priorité.** L'utilisateur saisit son SIRET (14 chiffres) ou son SIREN. On appelle
   `recherche-entreprises.api.gouv.fr/search?q=<siret>` et on lit `liste_idcc`. On affiche les
   conventions **déclarées** (badge « déclarée par l'employeur — DSN »), en listant **toutes**
   celles retournées (un établissement peut en déclarer plusieurs).
2. **Ne jamais conclure depuis le NAF.** Le NAF ne sert qu'à **suggérer** (« indice, à vérifier »)
   quand le SIRET est absent ou `9999`. Libellé obligatoire : « convention possible, à confirmer ».
3. **Toujours donner l'état** (en vigueur / étendue / non étendue / dénoncée) et le lien
   Légifrance/KALI, et rappeler que **l'activité réelle de l'entreprise** tranche en cas de doute.
4. **Calculateurs** : ne les ouvrir que lorsque l'IDCC est **certain** et que la classification
   (position/coefficient) et la date sont connues ; sinon afficher la règle légale (Code du
   travail) + renvoi à l'article conventionnel, sans chiffrer.

### 2.10 Minima conventionnels

- Source réelle : **KALI** (TM « Textes Salaires »), tables HTML (cf. §2.1).
- **Pas de jeu de données officiel structuré** dédié ; le BOSS ne couvre pas les minima de branche.
- Semi-officiel utile : grilles de classification Dares (Acemo) de la page §2.3.
- Structurabilité : **moyenne** — extraction faisable, mais un adaptateur par convention et par
  catégorie (ETAM / IC / ouvriers / employés…), avec gestion des dates d'effet.

### 2.11 NAF → IDCC

- **Officiel** : Dares, « Table de passage entre la convention collective (code IDCC) et le
  secteur d'activité (code APE) » (XLS ~629 Ko), depuis
  `https://travail-emploi.gouv.fr/table-de-correspondance-entre-secteur-dactivite-et-convention-collective`.
  **Non extrait en direct** : la page est protégée par un WAF (redirection en boucle) ; l'URL
  exacte du fichier reste à confirmer. Le miroir `code.travail.gouv.fr/fiche-ministere-travail/…`
  ne reprend pas cette page.
- **Doctrine** : un même NAF renvoie à plusieurs IDCC ; c'est l'**activité réelle** qui détermine
  la convention. Des sources privées (LégiSocial : 2 049 rattachements, 534 codes NAF) le
  rappellent explicitement.
- **Conclusion** : NAF → IDCC = **POSSIBLE** uniquement, jamais « certain ».

## 3. Modèle SQLite proposé

```sql
-- Une ligne par IDCC (source : fichier Dares mensuel + métadonnées KALI).
CREATE TABLE IF NOT EXISTS collective_agreement (
  idcc           TEXT PRIMARY KEY,        -- normalisé 4 chiffres : "1486"
  titre          TEXT NOT NULL,           -- libellé officiel Dares
  titre_court    TEXT,
  legitext       TEXT,                    -- KALICONT… (conteneur KALI)
  texte_base     TEXT,                    -- KALITEXT… du texte de base
  etat           TEXT,                    -- VIGUEUR_ETEN | VIGUEUR_NON_ETEN | ABROGE | …
  actif          INTEGER NOT NULL DEFAULT 0,
  regime         TEXT,                    -- Général | Agricole
  champ          TEXT,                    -- National | Local
  date_signature TEXT, date_effet TEXT, date_fin TEXT,
  nouvelle_idcc  TEXT,                    -- NouvIDCC (fusion/remplacement)
  source         TEXT NOT NULL,           -- 'dares-suivi-2026-06' | 'kali'
  fetched_at     INTEGER
);

-- Arborescence KALI (KALISCTA) : fil d'Ariane pour citer une règle.
CREATE TABLE IF NOT EXISTS agreement_section (
  id         TEXT PRIMARY KEY,            -- KALISCTA…
  idcc       TEXT NOT NULL REFERENCES collective_agreement(idcc),
  legitext   TEXT,                        -- KALITEXT… porteur
  parent_id  TEXT REFERENCES agreement_section(id),
  titre      TEXT,
  niveau     INTEGER,
  path       TEXT,                        -- "Texte de base > Titre III > Jours fériés"
  date_debut TEXT, date_fin TEXT, etat TEXT
);

-- Règle extraite, rattachée à un article KALIARTI.
CREATE TABLE IF NOT EXISTS agreement_rule (
  id            INTEGER PRIMARY KEY,
  idcc          TEXT NOT NULL REFERENCES collective_agreement(idcc),
  article_id    TEXT,                     -- KALIARTI…
  article_num   TEXT,                     -- "3", "10.1", "annexe III"
  type          TEXT NOT NULL,            -- salaire_minimum | prime | preavis | conges |
                                          -- anciennete | classification | periode_essai | jour_ferie
  categorie     TEXT,                     -- position / coefficient / ETAM / IC / ouvrier…
  valeur        REAL,
  valeur_texte  TEXT,
  unite         TEXT,                     -- EUR/mois | EUR/an | jours | mois | % | coefficient
  article_source TEXT,                    -- référence citée dans le texte
  valid_from    TEXT, valid_to TEXT,
  source        TEXT NOT NULL,            -- 'kali-<KALITEXT>'
  confidence    TEXT NOT NULL DEFAULT 'extrait'  -- extrait | deduit | heuristique
);
CREATE INDEX IF NOT EXISTS agreement_rule_lookup ON agreement_rule(idcc, type, valid_from);

-- SIRET/SIREN → IDCC, avec méthode et confiance (ne jamais fusionner les niveaux).
CREATE TABLE IF NOT EXISTS company_agreement (
  siret          TEXT NOT NULL,
  siren          TEXT,
  idcc           TEXT,                    -- NULL si IDCC 9999 (non déclaré)
  method         TEXT NOT NULL,           -- 'dsn-declared' | 'api-recherche-entreprises' | 'naf-suggested'
  confidence     TEXT NOT NULL,           -- 'certain-declare' | 'probable' | 'possible'
  declared_month TEXT,                    -- "2026-07"
  source         TEXT NOT NULL,
  fetched_at     INTEGER,
  PRIMARY KEY (siret, idcc, method)
);
```

**Règle de confiance à coder en dur :**
- `dsn-declared` / `api-recherche-entreprises` → **`certain-declare`** (l'employeur l'a déclaré ;
  il peut y en avoir plusieurs).
- `naf-suggested` → **`possible`** uniquement, jamais « certain ».

## 5. Calculateurs : déterministes vs non

### Sûrs (règle nationale unique, Code du travail déjà en base)

| Calculateur | Base | Condition |
| --- | --- | --- |
| Comparaison au SMIC | SMIC versionné (Urssaf/arrêté) | toujours |
| Préavis légal | `L1234-1`, `R1234-1` ; démission `L1237-1` | **si** la convention ne prévoit pas mieux |
| Congés payés légaux | `L3141-3` (2,5 j/mois) | toujours |
| Liste des jours fériés | `L3133-1` | toujours |
| Indemnité légale de licenciement | `L1234-9`, `R1234-2` | ancienneté ≥ 8 mois |
| Majoration légale des heures sup | `L3121-28`, `L3121-33` | taux légal, hors accord de branche/entreprise |

### NON déterministes (dépendent de la convention, de la classification, de la date)

- **Préavis conventionnel** : nécessite le bon IDCC **et** la catégorie (ex. HCR, BTP, Syntec).
- **Minima conventionnels** : grille + position/coefficient + date d'effet (tables hétérogènes).
- **Primes** (ex. HCR : prime TVA, prime tuteur) et **avantages** (repas, blanchissage).
- **Indemnités et ancienneté conventionnelles**, **jours fériés conventionnels** (HCR : jours
  autres que le 1er mai).
- **Conventions départementales/régionales** (BTP) : la convention nationale peut être complétée
  par une convention locale (933 conventions locales dans le fichier Dares).

→ Pour ces cas : **ne pas chiffrer**, afficher la règle applicable (article + lien) et la
condition d'éligibilité, avec un avertissement « vérifiez votre position/coefficient ».

## 6. Risques

1. **Fausse précision**
   - NAF → IDCC : indice seulement (multi-rattachements, activité réelle prime). Bannir le mot
     « certain » hors SIRET déclaré.
   - Un SIRET peut déclarer **plusieurs** IDCC (205 458 cas en 2026-07) : afficher la liste, pas
     un choix arbitraire.
   - `IDCC 9999` : ne rien affirmer.
   - Décalage DSN de **plusieurs mois** : un changement de convention récent n'apparaît pas.
2. **RGPD** : le SIRET/IDCC est une donnée **professionnelle** (entreprise), pas personnelle.
   Ne pas journaliser d'association SIRET ↔ requête d'un utilisateur identifiable ; ne pas
   conserver d'IP. API Entreprise interdit la commercialisation (non retenue).
3. **Licences** : KALI `fr-lo` et jeu SIRET `LO 2.0` → réutilisation commerciale OK avec
   attribution de la source. Licence du fichier Dares **à confirmer**. recherche-entreprises :
   code MIT, données LO 2.0. Ne pas réutiliser API Entreprise.
4. **Fraîcheur / cohérence** : KALI quotidien vs DSN trimestriel vs liste Dares mensuelle →
   versionner chaque table (`source`, `fetched_at`) et afficher la date de mise à jour.

## 7. Quick win vs plan complet

### Quick win (1 à 2 semaines) — « Trouver ma convention collective »

1. Ingérer le **fichier Dares mensuel** → `collective_agreement` (idcc, titre, etat, actif, champ).
2. Page SIRET : appeler **recherche-entreprises**, lire `liste_idcc`, joindre
   `collective_agreement`, afficher badges « déclarée (DSN, mois) » + lien Légifrance, et
   **lister toutes** les conventions.
3. Repli nom d'entreprise (même API) ; NAF **uniquement** en « indice, à confirmer ».
4. Aucun calculateur conventionnel : seulement les règles du Code du travail + renvoi à l'article
   de branche. Mettre en avant les 18 conventions déjà ingérées, sinon lien Légifrance.

### Plan complet (3 à 6 mois)

1. `agreement_section` depuis KALI (ou `kali-data` pour le fil d'Ariane).
2. `agreement_rule` : parseurs **par convention** pour les grilles de salaires (tables HTML),
   avec `valid_from`/`valid_to` et `confidence`.
3. Versionner le SMIC (`valid_from`/`valid_to`) depuis l'arrêté/Urssaf.
4. Calculateurs conventionnels **conditionnés** : IDCC certain + classification + date ; sinon
   règle légale + avertissement.
5. Table NAF→IDCC (Dares) marquée `possible`, jamais utilisée seule.
